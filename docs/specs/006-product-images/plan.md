# 006 — Plan: product images with placeholders

Spec: [spec.md](spec.md) · Tasks: [tasks.md](tasks.md) · Issue: #19

## Context

Every product needs an image before the Catalog epic builds category and product pages (FR-8), but we have no product photos. This story adds original placeholder artwork per builder category, seeds `ProductImage` rows that point to it by path, and adds one reusable `next/image` component with a fallback. `/products` uses it now, and real images later only change data.

## Summary

- **No schema change, no migration.** `ProductImage` (`url`, `alt`, `sortOrder`, cascade delete) already exists in [prisma/schema.prisma](../../../prisma/schema.prisma), and `--reset` already truncates it ([prisma/seed/write.ts](../../../prisma/seed/write.ts)).
- **No `next.config.ts` change.** `next/image` serves `.svg` sources unoptimized automatically (`node_modules/next/dist/docs/01-app/03-api-reference/02-components/image.md`, "dangerouslyAllowSVG").
- **Placeholders are generated once by a script and committed.** The script renders `lucide-react` icons with `react-dom/server`, both already dependencies, so nothing new is installed.
- **Seed:** an optional `images` field per part, defaulting to the category placeholder. Images are written only for products that have none.

## Placeholders

`lib/placeholders.ts` is client-safe, with no imports from server code:

```ts
export const PLACEHOLDER_DIR = "/images/placeholders"
export function placeholderUrl(name: string) // → "/images/placeholders/<name>.svg"
// Extra views for multi-image parts, with the alt text suffix each one gets
export const PLACEHOLDER_VIEWS = { box: "in the box", detail: "detail view" }
```

`scripts/generate-placeholders.tsx`, run with `pnpm images:placeholders` (`tsx scripts/generate-placeholders.tsx`):

- Has a map from name to icon: `cpu`: Cpu, `motherboard`: CircuitBoard, `memory`: MemoryStick, `storage`: HardDrive, `gpu`: Gpu, `case`: PcCase, `psu`: PlugZap, `cpu-cooler`: Fan, `box`: Package, `detail`: ScanSearch.
- For each name, it renders `<svg xmlns viewBox="0 0 240 240" width="240" height="240"><Icon x={72} y={72} width={96} height={96} color="#808080" strokeWidth={2} /></svg>` with `renderToStaticMarkup`. The icon is 40% of the width, on a transparent background.
- It prepends `<!-- Generated by scripts/generate-placeholders.tsx. Icon: Lucide (ISC License) -->` and writes `public/images/placeholders/<name>.svg`.
- `#808080` is a fixed mid-gray. An SVG loaded through `<img>` can't read CSS variables. This gray contrasts about 3.9:1 on light `muted` and 3.6:1 on dark `muted`, so it reads on both.
- The category names are checked against `builderCategories` keys, so a missing category fails the script.

## Seed

[prisma/seed/part-schema.ts](../../../prisma/seed/part-schema.ts):

```ts
const imageUrl = text().refine(
  (url) => (url.startsWith("/") && !url.startsWith("//")) || url.startsWith("https://"),
  "must be a path starting with / or an https:// URL"
)
images: z.array(z.strictObject({ url: imageUrl, alt: text().optional() })).min(1).max(4).optional()
```

- The schema's existing `.transform` fills in `images` (it already knows `category` and `name`):
  - A missing `images` becomes `[{ url: placeholderUrl(category), alt: name }]`.
  - A missing `alt` becomes `name` for the first entry. Later entries get `${name} — ${view}`, where `view` comes from `PLACEHOLDER_VIEWS` when the URL is that view's placeholder, else `image N`.
- After the transform, `images` is always `{ url; alt }[]`, and `sortOrder` is the array index.
- `describeIssue` in [format-errors.ts](../../../prisma/seed/format-errors.ts) already reports custom refine messages, so no change is needed there.

[prisma/seed/write.ts](../../../prisma/seed/write.ts):

- The existing-products query also selects `_count: { select: { images: true } }`, giving a `Map<sku, imageCount>`.
- **Create:** `images: { create: part.images.map((image, i) => ({ ...image, sortOrder: i })) }`.
- **Update:** add the same nested `images.create` to the update data **only** when the count is 0. Products that already have images are left alone.
- `SeedCounts` gains `images`, the number of rows added. [prisma/seed.ts](../../../prisma/seed.ts) appends `, ${images} images added` to the summary.

## Component

`components/product/product-image.tsx` is a server component:

```tsx
type ProductImageProps = {
  image: { url: string; alt: string } | null
  productName: string
  sizes: string
  loading?: "lazy" | "eager"
  className?: string
}
```

- **Outer box:** `<div className={cn("relative aspect-square overflow-hidden rounded-md bg-muted", className)}>`.
- **With an image:** `<Image src={image.url} alt={image.alt} fill sizes={sizes} loading={loading ?? "lazy"} className="object-contain" />`.
- **Without:** `<div role="img" aria-label={`No image available for ${productName}`} className="flex size-full items-center justify-center text-muted-foreground"><ImageOffIcon aria-hidden className="size-1/3" /></div>`.
- Uses token utilities only, and `cn()` from [lib/utils.ts](../../../lib/utils.ts).

## Tests

- **[validate.test.ts](../../../prisma/seed/validate.test.ts), new `describe("images")`:**
  - A part with no `images` gets the default, with `alt` = name.
  - Explicit `[cpu, box, detail]` keep their order, and the alts are name, "name — in the box" and "name — detail view".
  - `images/x.svg`, `//cdn/x.svg` and `http://x/y.png` are rejected with the message above.
  - `alt: ""` is rejected.
  - An `https://` URL is accepted.
- **[coverage.test.ts](../../../prisma/seed/data/coverage.test.ts):**
  - Every local image URL in the validated seed exists as a file under `public/`.
  - Every `builderCategories` key has `public/images/placeholders/<key>.svg`, and `box.svg` and `detail.svg` exist.
  - The catalog has 5–6 parts with more than one image, at least one with exactly 2 and one with exactly 3.
- **[e2e/products.spec.ts](../../../e2e/products.spec.ts):** in the Ryzen row, `getByRole("img", { name: "AMD Ryzen 5 7600" })`, then `scrollIntoViewIfNeeded()` (thumbnails load lazily), then `expect.poll(() => img.evaluate(el => el.complete && el.naturalWidth))` to be greater than 0.
